# lattice v0.7.0

## Breaking changes

- **`Qwen35Model::generate_with_batch_prefill` (`crates/inference/src/forward/batch_prefill.rs`)
  removed.** It was marked `#[deprecated(since = "0.5.1")]` in v0.6.0 with removal
  targeted at this release (#807): a standalone decode loop that predated
  `Qwen35Model::generate` / `generate_streaming` delegating their own prompt phase to
  the same batched-prefill core (`prefill_tokens_batched_for_generate`), leaving it an
  unused, redundant duplicate. Migrate to `Qwen35Model::generate`
  (`crates/inference/src/model/qwen35/generation.rs`) for a drop-in replacement — it
  takes the same `GenerateConfig` and returns the same `GenerateOutput`. For streaming
  output, use `Qwen35Model::generate_streaming` instead, which takes the same
  `GenerateConfig` and returns the same `GenerateOutput` but additionally requires an
  `on_token: impl FnMut(&str)` callback invoked as each token is produced.

- `CrossEncoderModel::score_with_hook` and `CrossEncoderModel::score_batch_with_hook` now return
  `Result<f32, InferenceError>` and `Result<Vec<f32>, InferenceError>` instead of `f32` and
  `Vec<f32>`. Both methods now ask the supplied `LoraHook` to check its own declared projection
  geometry against the model's BERT dimensions before running the forward pass, and return
  `InferenceError::InvalidInput` when it reports a mismatch. `LoraAdapter` implements that check;
  a hook that leaves `LoraHook::validate_against_bert` at its default is trusted. Previously a
  geometry mismatch was not detected on this path: an adapter declaring a `d_out` smaller than the
  projection's own width let the forward pass run anyway, writing an update across a prefix of the
  projection row and returning a plausible-looking relevance score.

  Migration is one character at most call sites:

  ```rust
  // before
  let score = cross_encoder.score_with_hook(query, document, &adapter);
  // after
  let score = cross_encoder.score_with_hook(query, document, &adapter)?;
  ```

  The infallible `score` and `score_batch` methods are unchanged and keep their `f32`/`Vec<f32>`
  signatures.

## Fixes

- `lattice_tune::lora::apply_lora` now requires the `output` slice to be exactly `d_out` wide
  instead of at least `d_out` wide. The inequality accepted an adapter that under-declared
  `d_out`, and the accumulate loop then wrote only `output[..d_out]` — applying an update
  computed for a geometry the model does not have across a prefix of the projection row and
  leaving base weights across the rest, with no panic, no error, and a finite result. An adapter
  that declares its true projection width is unaffected; one that under-declares is now dropped
  instead of partially applied.

- The two HTTP serve binaries now emit an SSE error envelope when generation fails mid-stream,
  preserving `finish_reason: "stop"` for genuine stop conditions. The standalone `lattice_serve`
  daemon also rejects mismatched request model ids with `model_not_found` (#663, #933).
