# lattice v0.7.0

133 commits since v0.6.1. The minor bump is required rather than chosen: this release removes a
deprecated public method, and under 0.x semver a breaking change takes the minor.

Two themes dominate. The first is that grammar-constrained generation became reachable from the
HTTP server, which had been the missing half of a compiler that already existed. The second is a
broad input-validation sweep across the loaders and decode paths, replacing panics and unchecked
allocations with typed errors at the boundary.

A large amount of Gemma 4 and Qwen3.5 vision groundwork also landed. It is deliberately described
below as groundwork, and the limits are listed at the end rather than implied by omission.

## Breaking changes

Enumerated from `cargo-semver-checks` run against the published 0.6.1 baseline with all lints
forced (`--release-type patch`), so this list is generated rather than recalled. `lattice-transport`
has no breaking changes.

### lattice-inference

- **`Qwen35Model::generate_with_batch_prefill` (`crates/inference/src/forward/batch_prefill.rs`)
  removed.** It was marked `#[deprecated(since = "0.5.1")]` in v0.6.0 with removal
  targeted at this release (#807): a standalone decode loop that predated
  `Qwen35Model::generate` / `generate_streaming` delegating their own prompt phase to
  the same batched-prefill core (`prefill_tokens_batched_for_generate`), leaving it an
  unused, redundant duplicate. Migrate to `Qwen35Model::generate`
  (`crates/inference/src/model/qwen35/generation.rs`) for a drop-in replacement — it
  takes the same `GenerateConfig` and returns the same `GenerateOutput`. For streaming
  output, use `Qwen35Model::generate_streaming` instead, which takes the same
  `GenerateConfig` and returns the same `GenerateOutput` but additionally requires an
  `on_token: impl FnMut(&str)` callback invoked as each token is produced.

- **`Qwen35Config` gains five public fields** for vision support: `vision_config`,
  `image_token_id`, `video_token_id`, `vision_start_token_id`, `vision_end_token_id`
  (`crates/inference/src/model/qwen35_config.rs:274-286`). **`RopeParams` gains two**:
  `mrope_section` and `mrope_interleaved` (`:310-314`). Code that builds either with a struct
  literal will no longer compile. Use `..Default::default()` or the deserialization path.

- **Variants added to exhaustive enums**, so exhaustive `match` arms over them break:
  `ApiError::{ServerError, ServiceUnavailable, UnsupportedMediaType}`
  (`crates/inference/src/serve/mod.rs`), `InferenceError::GrammarConstraintBlocked`
  (`crates/inference/src/error.rs:40`), and
  `RotationId::{AttentionOutputR3, MlpDownR4}` (`crates/inference/src/quant/quarot/plan.rs`).
  Add a `_ =>` arm.

- **Signature changes.** `speculative::mtp_verify_draft` takes 8 parameters (was 7),
  `speculative::mtp_verify_draft_with_seed` 9 (was 8), and `speculative::rejection_sample_draft`
  7 (was 6) — these carry the sampling temperature now threaded through the MTP rejection
  verifier. `weights::q8_weights::quantize_gdn_weights` takes 2 (was 1).
  `BpeTokenizer::vocab_bytes` takes 1 parameter (was 0).

### lattice-tune

- **`LabelingResult` is no longer externally constructible and its public fields are gone.**
  `labels`, `confidence`, `raw_response`, `error` and `latency_ms` are no longer public fields,
  a private `source` field was added, and `LabelingResult::success` takes 5 parameters (was 4)
  (`crates/tune/src/distill/pipeline/types.rs`). This is the non-forgeable teacher-provenance
  change: a distillation label now carries where it came from, and that guarantee only holds if
  callers cannot hand-build the struct. Construct via `LabelingResult::success` and read through
  the accessors.
- **`LoraAdapter`'s `config` and `layers` public fields are no longer public**
  (`crates/tune/src/lora/mod.rs`). Use the accessors.
- **`MicroLoraConfig` gains a `last_layer` field** (`crates/tune/src/lora/train.rs:63`), so struct
  literals need updating.

### lattice-fann

- **Six `ShaderType` variants removed**: `SoftmaxMax`, `SoftmaxExpSum`, `SoftmaxNorm`,
  `SgdMomentum`, `Adam`, `AdamW` (`crates/fann/src/gpu/shader_manager.rs`).

### lattice-embed

- **`MAX_TEXT_CHARS` is deprecated** (`crates/embed/src/service/mod.rs:46`). The guard counts
  bytes, not chars, and `TextTooLong` now reports bytes to match. Deprecation only, still present.

## Changed defaults

- **`lattice-embed` default features are now `["native", "download"]`**, up from `["native"]` in
  v0.6.1. A build that takes default features therefore pulls the first-use model download stack
  (`ureq` → `rustls` → `ring`) and `BertModel::from_pretrained` will fetch on first use. This
  keeps a plain `cargo run -p lattice-embed --bin embed` working out of the box.

  It matters for two cases. Cross and edge builds should drop it with `--no-default-features
  --features native`, because `ring` does not cross-compile to aarch64 under zig. WASM builds are
  unaffected even with defaults active, since inference gates its download stack to non-wasm
  targets, so `--features wasm` resolves download-free. See #1095.

  `lattice-inference` default features are unchanged.

## Structured output

`lattice_serve` accepts strict `response_format: {"type": "json_schema", ...}` and compiles the
schema to a grammar that constrains decoding (#1018). The JSON Schema compiler and its
fail-closed caps already existed; what was missing was the request-shape wiring and a Metal
generation path that could tell a satisfied grammar from a dead end.

- Terminal grammar states are now treated as a successful stop on the Metal paths rather than a
  blocked constraint (#1067). Since Metal is `lattice_serve`'s generation path, this was the
  difference between a schema-conforming completion returning an error and returning a result.
- Three correctness gaps in the JSON-Schema and GBNF compilers are fixed, along with rejection of
  invalid escapes and control bytes in string grammars, and clean termination of terminal states.
- Constrained decode is substantially faster on schemas that exceed the precomputed state cap, via
  a trie-accelerated mask for over-cap states (#1019, addressing #734).

## Serving

- Prometheus `/metrics` endpoint on `lattice_serve` (#976).
- Bounded Metal-worker admission with explicit backpressure rejection rather than unbounded
  queueing (#939), and the Metal path now mirrors the CPU path's prompt and decode-budget
  admission bound (#922).
- Mid-stream generation failures emit an SSE error envelope, preserving `finish_reason: "stop"`
  for genuine stop conditions. `lattice_serve` rejects mismatched request model ids with
  `model_not_found` (#663, #933).

## Quantization

- New W3 `Q3Block` 3-bit weight format (#978) with Metal decode kernels for the Q3 MLP weight
  layout (#1014), under ADR-072 P1. This is an internal format in this release; see the
  limitations section.
- QuaRot online R3/R4 rotation contract and reference implementation (#1022).

## Model support groundwork

**Gemma 4 (ADR-082, stages 0 through 5).** BPE tokenizer parity against HF goldens (#993), config
parsing and loader preflight (#996), per-op text math kernels checked against HF goldens (#999),
a shared-KV cache with donor-slot indirection (#1002), a tensor-manifest fixture and asset plan
(#991), and a text-only CPU forward (#1008).

**Qwen3.5 vision (ADR-069).** Vision config parsing and `model.visual` tensor loading (#988), a
vision tower forward checked against HF goldens (#994) and its Metal counterpart (#997), the
patch-merger projection (#998), M-RoPE position and cos/sin table construction (#1004) with the
3-axis Metal variant (#1011), Metal visual-embedding injection (#1009), and an end-to-end CPU
path (#1005). Pooled image and text VLM embedding extraction (#1007) is exposed through a new
`VisionEmbeddingModel` in `lattice-embed` (#1013).

## Performance

- Trie-accelerated grammar mask for over-cap states (#1019).
- Vectorized backward-tape hot loops in `lattice-tune` (#943, first stage of #737).
- `bench-compare` now takes the machine-wide bench and GPU locks itself, samples ambient CPU idle
  before, between and after phases, refuses to certify a run that fell below the idle floor, and
  prints a run-conditions block recording refs, targets, features and lock dispositions (#1119).

## Tooling and observability

- Layer pruning scorer exposed on the CLI (#1043).
- Optional MoE routing-trace collector for offline agreement checks (#920).
- `os_signpost` instrumentation of the Metal decode path (#1029).

## Fixes

**Input validation and fail-closed loading.** Shapes and sizes are validated before allocation;
weight loader artifacts and Q8 weights are validated at ingress; RoPE positions are validated
before dispatch; allocation-driving config fields are bounded and manifest shard paths contained
in the Qwen3.5 loader; all loaders now fail closed on a missing `config.json`. Empty prompts are
rejected with a typed error in shared preflight on every path (#856), and zero-budget, empty-prompt
and NaN decode guards were added. Non-finite LoRA alpha is rejected at parse, config and manifest
boundaries, and LoRA adapter geometry is validated in `Qwen35Model::set_lora`.

**Correctness.** The top-1 logits oracle uses first-wins tie-break to match the greedy contract.
Sampling temperature is threaded through the MTP rejection verifier. BERT LoRA is applied per token
row. Detokenizer finalization is correct on EOS and grammar stop, with SentencePiece ID and
added-token guards and exact grammar byte tables. `lattice-fann` enforces its hidden-Softmax
placement invariant and preserves extreme activation inputs. The `lattice-embed` cosine fast path
verifies its unit-norm assumption.

**Robustness.** The non-`metal-gpu` `generate` stub returns a `Result` instead of panicking (#917).

**Embeddings.** Standalone builds can read F16 and BF16 weights and can cross-compile.
`TextTooLong` reports bytes, matching what the guard actually counts. Caller text is validated
before the retrieval instruction is applied.

**Training.** `lattice-tune` fails closed on placeholder train steps, and distillation labels carry
non-forgeable teacher provenance.

**CI and build plumbing.** The parity reference loads from the verified snapshot, the bench-compare
gate no longer rejects long PR descriptions, sharded checkpoints are accepted in dev-run pre-check
helpers, the macOS app footer shows the real `lattice_serve` invocation, and ingress and backward
SIMD contracts are documented.

## Known limitations

These landed in-tree in this release and are **not** reachable capabilities yet. They are listed
so that the feature sections above are not read as claiming more than they do.

- **Gemma 4** reaches a text-only CPU forward. There is no Metal path and no end-to-end validated
  generation for it in this release.
- **Qwen3.5 vision** has its tower, projection, M-RoPE and injection paths checked against HF
  goldens per stage, but end-to-end vision generation is not validated in this release, and the
  serve-side image content-parts wiring is not merged.
- **W3 / Q3 3-bit quantization** has a weight format and Metal decode kernels, but no binary in
  this release produces or runs a Q3 model. It is preparatory infrastructure.
- **Structured output** is wired and its two known blockers are fixed, but `$ref` siblings that
  narrow their target are currently dropped, which can compile a grammar wider than the schema it
  came from (#1145). Treat `strict` accordingly until that lands.
