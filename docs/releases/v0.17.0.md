# lattice v0.17.0

**Date**: 2026-11-22
**Previous**: v0.16.0

## Changelog

### Breaking changes

#### Gemma and ERNIE unknown-token declarations

Gemma and ERNIE tokenizer loaders now reject an explicit `model.unk_token: "<unk>"`
declaration when `<unk>` is absent from `model.vocab`, including exports that list
it only in `added_tokens`. Missing or null `model.unk_token` retains its previous
behavior. ([#2812](https://github.com/ohdearquant/lattice/pull/2812))

The same loaders also refuse, at load, a `model.unk_token` that is not a string or that uses an unsupported
spelling. ([#2800](https://github.com/ohdearquant/lattice/pull/2800), [#2812](https://github.com/ohdearquant/lattice/pull/2812))

The two exports lattice pins as tokenizer test fixtures both declare
`model.unk_token` as `"<unk>"` and store `model.vocab` as an object:

| Export                                                                                                      | Revision                                   | Vocabulary entries | `<unk>` vocabulary ID | Matching `added_tokens` entries |
| ----------------------------------------------------------------------------------------------------------- | ------------------------------------------ | ------------------ | --------------------- | ------------------------------- |
| [google/gemma-4-E2B-it](../../crates/inference/tests/fixtures/gemma4/tokenizer/manifest.json)               | `9dbdf8a839e4e9e0eb56ed80cc8886661d3817cf` | 262144             | 3                     | One: ID 3, `special: true`      |
| [PaddlePaddle/PaddleOCR-VL-1.6](../../crates/inference/tests/fixtures/paddleocr_vl/tokenizer/manifest.json) | `c5630abae1d940eafe0697512a0325494b02ab42` | 100295             | 0                     | One: ID 0, `special: true`      |

Both list `<unk>` in `model.vocab`, so neither has the refused layout, and both
still load: the tokenizer golden tests for these two revisions pass with this
change. Other exports that declare `<unk>` only in `added_tokens` now fail to load
with the named error.

#### Qwen3 fused projection storage in `lattice-weights`

`ShardedQwenBacking` stores each layer's Q/K/V and gate/up projections once, fused:
the `q_proj`, `k_proj`, `v_proj`, `gate_proj` and `up_proj` fields are replaced by
`fused_qkv` (rows of W_q, W_k and W_v concatenated) and `fused_gate_up` (rows of
W_gate and W_up concatenated). `QwenLayerWeights::fused_qkv` and
`QwenLayerWeights::fused_gate_up` change from `Vec<f32>` to `Cow<'a, [f32]>`, borrowed
when the owner already holds the fused buffer. Code that read the per-projection
fields should take the subslices of the fused buffers, or use the `q_proj_weight`,
`k_proj_weight`, `v_proj_weight`, `gate_proj_weight` and `up_proj_weight` views on
`QwenLayerWeights`, which keep their types.
([#2785](https://github.com/ohdearquant/lattice/pull/2785))

#### Qwen3 token embedding table type

`QwenWeights::embed_tokens` changes from `Tensor2D<'a>` to `EmbeddingTable<'a>`, an enum holding either an f32
table (`EmbeddingTable::F32(Tensor2D)`) or a BF16 table kept as its raw bits and widened to f32 per row on read.
Code that read `embed_tokens.data` should use `rows()`, `cols()`, `copy_row_into` or `to_f32_vec`, or match the
`F32` variant. `EmbeddingTable` is re-exported at `lattice_inference::weights` and
`lattice_inference::weights::f32_weights`.
([#2786](https://github.com/ohdearquant/lattice/pull/2786), [#2808](https://github.com/ohdearquant/lattice/pull/2808))

#### `BertConfig::position_offset`

`BertConfig` (`lattice-arch`, re-exported as `lattice_inference::BertConfig`) gains `position_offset: usize`, the
position-embedding row the first token reads. Code that builds a `BertConfig` with a struct literal must add it: `0`
for BERT numbering, `pad_token_id + 1` for RoBERTa-family checkpoints. Configs read from `config.json` set it.
([#2854](https://github.com/ohdearquant/lattice/pull/2854))

#### `PreparedSystemOne` fields

`lattice_serve::serve::systemone::PreparedSystemOne` gains `label_ids: Vec<u32>`, the label token ids its prompt was
assembled against, and `input_tokens: usize`, the input token count the response reports. Code that builds it with a
struct literal must supply both.
([#2865](https://github.com/ohdearquant/lattice/pull/2865), [#2866](https://github.com/ohdearquant/lattice/pull/2866))

### Changed outputs

These fixes change the tokens or vectors some inputs produce. Each one moves lattice toward the reference implementation named. Where an entry names a new embedding identity, cached vectors keyed on the old identity are not reused; the other entries leave identities unchanged.

- **XLM-RoBERTa, RoBERTa and CamemBERT positions.** These checkpoints number positions from `pad_token_id + 1`, and the BERT encoder read row `i` for token `i`. `multilingual-e5-base` therefore shifted every position by two rows and scored cosine 0.82 to 0.96 against the reference. `BertConfig` gains `position_offset` and `max_positions()`, and the e5-base identity moves to `multilingual-e5-base-native-v2`. BERT checkpoints that number from row 0, such as `multilingual-e5-small` and the bge family, are unchanged. ([#2854](https://github.com/ohdearquant/lattice/pull/2854))
- **paraphrase-multilingual-MiniLM-L12-v2 truncates at 128 tokens**, the sentence-transformers `max_seq_length` of the reference model. It used to embed up to the 512 positions its table allows, so a 290-token paragraph scored cosine 0.733 against the reference. The limit is its own constant, `PARAPHRASE_MULTILINGUAL_REFERENCE_INPUT_LIMIT`, pinned to the embedding identity `paraphrase-multilingual-minilm-l12-v2-native-v2`. ([#2861](https://github.com/ohdearquant/lattice/pull/2861), [#2885](https://github.com/ohdearquant/lattice/pull/2885))
- **WordPiece pre-tokenization matches Hugging Face `BertNormalizer` and `BertPreTokenizer`** for every Unicode scalar value. It removes Unicode "other" characters except tab, newline and carriage return, strips accents by NFD decomposition (`unicode-normalization-alignments` 0.1.12, pinned to the version `tokenizers` uses), and classifies punctuation by BERT's Unicode categories. The embedding identity moves from `wordpiece-single-v2` to `wordpiece-single-v4` (v3 in #2784, v4 in #2836), and its `tokenizer.program` from `lattice-tokenizer-v1` to `lattice-tokenizer-v2`. ([#2784](https://github.com/ohdearquant/lattice/pull/2784), [#2836](https://github.com/ohdearquant/lattice/pull/2836))
- **WordPiece reads `model.continuing_subword_prefix`** from `tokenizer.json` and falls back to `##` only when the field is absent. ([#2752](https://github.com/ohdearquant/lattice/pull/2752))
- **SentencePiece `Precompiled` normalizers are applied** before segmentation, following `tokenizers` 0.22.2. The multilingual E5 models use one: in 0.16 the full-width `Ａ` encoded to an unknown token on `multilingual-e5-small`, where the reference produces the id for `A`. The tokenizer identity records the normalizer's character map. The normalizer `Sequence` nesting depth is bounded. ([#2794](https://github.com/ohdearquant/lattice/pull/2794), [#2801](https://github.com/ohdearquant/lattice/pull/2801))
- **BPE pre-tokens split on Unicode letters (`\p{L}`)** for Qwen-family `tokenizer.json` files. The pre-tokenizer used `char::is_alphabetic()`, which also admits combining marks, letter numbers and circled letters, so words containing those marks stayed one pre-token. ([#2876](https://github.com/ohdearquant/lattice/pull/2876))
- **Gemma byte fallback is all-or-nothing per character**, as in Hugging Face `tokenizers`: a character with any byte token missing from the vocabulary becomes an unknown, and consecutive unknowns fuse into one. Tokenizers carrying all 256 byte tokens, as the shipped Gemma checkpoints do, are unaffected. The EmbeddingGemma2 input program becomes `gemma-bpe-text-bos-eos-v2`. Unsupported `model.unk_token` spellings and non-string values are refused at load on Gemma and ERNIE tokenizers (see Breaking changes for the `<unk>` declaration). ([#2789](https://github.com/ohdearquant/lattice/pull/2789), [#2800](https://github.com/ohdearquant/lattice/pull/2800), [#2812](https://github.com/ohdearquant/lattice/pull/2812))
- **LayerNorm accumulates each row's mean in f64** and centres the variance on the exact mean, in the scalar, NEON and AVX2 bodies, the vision LayerNorm and the Qwen2-Audio post-pool LayerNorm. Constant rows now return `beta`, and rows with a large common offset get a correct variance. Outputs on ordinary rows move by rounding only. ([#2743](https://github.com/ohdearquant/lattice/pull/2743), [#2757](https://github.com/ohdearquant/lattice/pull/2757), [#2765](https://github.com/ohdearquant/lattice/pull/2765), [#2766](https://github.com/ohdearquant/lattice/pull/2766), [#2783](https://github.com/ohdearquant/lattice/pull/2783), [#2824](https://github.com/ohdearquant/lattice/pull/2824))
- **Ternary packing divides by the row alpha**, as documented. It multiplied by `1 / alpha`, so a weight just under `alpha / 2` could round to `±1` instead of `0`. ([#2754](https://github.com/ohdearquant/lattice/pull/2754))

### Added

- **`POST /v1/systemone`.** `lattice serve` on a directory holding a decider checkpoint (`decider_config.json` beside the weights) serves the multi-question decision endpoint. Each row's option letters are scored and calibrated with the checkpoint temperature. A refused request answers 422 with a `detail` message, a full queue 503, and a scorer failure 500. Scoring stops between rows once the caller hangs up, on both the CPU host and the serving worker. A row longer than the served window is refused with 422. ([#2859](https://github.com/ohdearquant/lattice/pull/2859), [#2860](https://github.com/ohdearquant/lattice/pull/2860), [#2865](https://github.com/ohdearquant/lattice/pull/2865), [#2866](https://github.com/ohdearquant/lattice/pull/2866), [#2871](https://github.com/ohdearquant/lattice/pull/2871), [#2884](https://github.com/ohdearquant/lattice/pull/2884), [#2886](https://github.com/ohdearquant/lattice/pull/2886))
- **Qwen3.5 option scoring.** `Qwen35Model::score_option_letters_batched` scores through the batched CPU prefill. `ScoringPrefix`, `Qwen35Model::prefill_scoring_prefix` and `score_option_letters_after_prefix` let one prefilled prefix serve any number of continuing prompts, and `score_option_rows_shared_prefix` builds on them. `KvCache` derives `Clone` and gains `fork`. ([#2864](https://github.com/ohdearquant/lattice/pull/2864), [#2867](https://github.com/ohdearquant/lattice/pull/2867), [#2869](https://github.com/ohdearquant/lattice/pull/2869))
- **`lattice serve --max-context`** bounds the CPU Qwen3.5 window, as the Metal server already did: the smaller of the model's window and the flag, or 32,768 when the flag is omitted, printed with its source at startup. `Qwen35Model::from_safetensors_with_max_context` builds the RoPE table at that window. The CPU model now covers every position its config declares (262,144 for current checkpoints) instead of a fixed 8,192. ([#2877](https://github.com/ohdearquant/lattice/pull/2877), [#2878](https://github.com/ohdearquant/lattice/pull/2878), [#2879](https://github.com/ohdearquant/lattice/pull/2879))
- **`lattice-transport` features.** Rayon is optional behind a default `parallel` feature, and Serde behind a default `serde` feature. With both off the numerical APIs run serially without either dependency edge. Default builds are unchanged. ([#2804](https://github.com/ohdearquant/lattice/pull/2804), [#2805](https://github.com/ohdearquant/lattice/pull/2805))
- **Chronos-2 request memory budget.** `set_request_memory_budget(Option<usize>)` refuses a request whose accounted peak of Chronos-owned storage exceeds the budget, before allocating. Models start with no budget. ([#2810](https://github.com/ohdearquant/lattice/pull/2810))
- **`lattice-weights`** gains `get_bf16_bits_owned`, and the QuaRot reader an owned f32 tensor read, used by `quantize_q4`. ([#2786](https://github.com/ohdearquant/lattice/pull/2786), [#2768](https://github.com/ohdearquant/lattice/pull/2768))
- **`bench_systemone_scoring` example** in `lattice-serve`: a paired measurement of `/v1/systemone` CPU scoring, shared prefix against per-row with a per-row A/A arm. ([#2890](https://github.com/ohdearquant/lattice/pull/2890))

### Performance

- **Qwen3.5 CPU prefill.** The GatedDeltaNet output walks the state matrix by rows, and value heads run in parallel per token, with logits bit-identical. A `/v1/systemone` request prefills the prefix its rows share once. ([#2892](https://github.com/ohdearquant/lattice/pull/2892), [#2867](https://github.com/ohdearquant/lattice/pull/2867), [#2871](https://github.com/ohdearquant/lattice/pull/2871))
- **AVX2 `matmul_bt`** runs each 4×8 tile as four 2×4 register blocks, so the accumulators stay in registers, with bit-identical output. ([#2896](https://github.com/ohdearquant/lattice/pull/2896))
- **Qwen3-Embedding memory.** The CPU path holds Q/K/V and gate/up once, as the fused buffers, keeps a BF16 token table as BF16 bits (half the table's memory; widening is exact, so embeddings are unchanged), pools the final row without copying the whole hidden-state matrix, and normalizes only the pooled rows. ([#2785](https://github.com/ohdearquant/lattice/pull/2785), [#2786](https://github.com/ohdearquant/lattice/pull/2786), [#2833](https://github.com/ohdearquant/lattice/pull/2833), [#2845](https://github.com/ohdearquant/lattice/pull/2845))
- **BERT and EmbeddingGemma scratch.** BERT packed attention allocates its buffers once per encode chunk instead of per sequence per layer, and EmbeddingGemma reuses one aligned per-encode scratch across layers. ([#2834](https://github.com/ohdearquant/lattice/pull/2834), [#2823](https://github.com/ohdearquant/lattice/pull/2823))
- **Qwen3.5 f16 RoPE tables** are built for the positions a call can read rather than all 262,144 declared positions (a 64 MiB table per embedding call before). ([#2880](https://github.com/ohdearquant/lattice/pull/2880))
- **`quantize_q4`** reads f32 tensors directly, so an untied 248320×4096 embedding no longer holds an f64 and an f32 copy together (about 8.1 GB plus 4.1 GB). ([#2768](https://github.com/ohdearquant/lattice/pull/2768))
- **BPE pre-tokenizer** inlines the ASCII letter test. ([#2883](https://github.com/ohdearquant/lattice/pull/2883))

### Fixes

- **Qwen3-Embedding cache.** A hit now requires a SHA-256 digest of the token ids to match, so two texts whose ids share the 64-bit hash no longer share an embedding, in memory or in a saved cache file. Changing the output width clears the cache. `cache_load` refuses a merge that would exceed `EMBEDDING_CACHE_CAP` and names the counts. ([#2751](https://github.com/ohdearquant/lattice/pull/2751), [#2769](https://github.com/ohdearquant/lattice/pull/2769), [#2835](https://github.com/ohdearquant/lattice/pull/2835), [#2847](https://github.com/ohdearquant/lattice/pull/2847))
- **Embeddings route** refuses BERT inputs longer than the smaller of the model's position limit and the tokenizer's `model_max_length`, instead of truncating them silently. ([#2793](https://github.com/ohdearquant/lattice/pull/2793))
- **`CachedEmbeddingService`** reports the wrapped service's model configuration. ([#2790](https://github.com/ohdearquant/lattice/pull/2790))
- **WordPiece** keeps over-limit words out of the word cache. ([#2788](https://github.com/ohdearquant/lattice/pull/2788))
- **Grammar.** `enum`, `const` and `$ref` string values are type-checked against an array-valued `type`, and string intersections survive mixed `$ref` terminals inside `anyOf`/`oneOf`. ([#2774](https://github.com/ohdearquant/lattice/pull/2774), [#2818](https://github.com/ohdearquant/lattice/pull/2818))
- **Sampling.** The top-p fallback returns a positive-probability candidate when the normalized sum finishes just below one. ([#2767](https://github.com/ohdearquant/lattice/pull/2767))
- **QuaRot MTP.** Converting a complete Qwen3.5 MTP head keeps the original final norm scale in a sidecar and applies it before the MTP head's normalization. ([#2807](https://github.com/ohdearquant/lattice/pull/2807))
- **ERNIE 4.5.** Configs with an invalid `rope_theta`, or whose RoPE angles overflow f32 at a valid position, are refused at load. ([#2706](https://github.com/ohdearquant/lattice/pull/2706), [#2770](https://github.com/ohdearquant/lattice/pull/2770))
- **Chronos-2.** An unrepresentable horizon and oversized requests are refused before allocating. ([#2698](https://github.com/ohdearquant/lattice/pull/2698), [#2771](https://github.com/ohdearquant/lattice/pull/2771))
- **Model downloads.** A stalled body is bounded by a 60 s input-idle timeout, so a server that stops sending no longer blocks every waiter for that file. ([#2775](https://github.com/ohdearquant/lattice/pull/2775))
- **`lattice` error lines** escape control characters in paths and errors. ([#2773](https://github.com/ohdearquant/lattice/pull/2773))
- **`lattice_inference::weights`** re-exports `EmbeddingTable` again. ([#2808](https://github.com/ohdearquant/lattice/pull/2808))
- **Dependencies.** `rusqlite` moves to 0.41 (bundled SQLite 3.54.1, RUSTSEC-2026-0459). It is optional: the inference backfill tool and `lattice-tune`'s `sqlite` feature. ([#2802](https://github.com/ohdearquant/lattice/pull/2802))

### Rescheduled

0.16.0 rescheduled to this release the move of the family configurations, weight bundles and model policy out of `lattice-arch` and the lower crates (ADR-103 Amendment 26). That refactor had not started at the 0.17.0 cut either, so it is no longer tied to a release number (ADR-103 Amendment 27) and is tracked in [#2899](https://github.com/ohdearquant/lattice/issues/2899). It still has release rules: it merges only while `main` carries an unreleased minor version, ships in a `0.x.0` release and never in a patch, and that release's notes carry the path map for the lower-crate paths it moves, such as `lattice_arch::qwen35_config`. Until it lands, each release's notes carry its status here.

Status at 0.17.0: not started.

## Release measurements

Compared with v0.14.0 at commit 19e746b6, the commit this release is cut from, on an x86_64 Linux host with an AMD Ryzen 7 PRO 8700GE (8 cores, 16 threads) and rustc 1.94.1. Each benchmark target ran as its own `scripts/bench-compare.sh <base> <head>` invocation at the script's default quick resolution, in ABBA order with default features on both sides. The inference target was chosen with `BENCHES_INFERENCE`: the default `elementwise_cpu_bench` (paired with the embed `simd` target), `inference_bench` (paired with `embeddings`), and `attention_dispatch_bench`, `kv_cache_f16_bench`, `tokenizer_bench`, `grammar_mask_bench` and `quarot_hadamard_bench` (each paired with `simd_opt_bench` filtered to `i8_dot_product` through `BENCHES_EMBED` and `BENCH_GROUPS_EMBED`). `tokenizer_bench` was restricted with `BENCH_GROUPS_INFERENCE` to the groups both versions declare, and re-runs and A/A runs narrowed their groups the same way. The thresholds below are this release's own acceptance rules, separate from the script's regression gate. A group counts as changed only when its whole ABBA range lies beyond ±5%. Every slower group that times library code was re-run at the same resolution; the two below reproduced, and the embedding SIMD groups that read slower in the first run did not. Every figure below is also confirmed against a same-commit A/A run (19e746b6 against itself) of the same groups: its distance from zero exceeds three times the largest bound the A/A run shows for that group. Runs refused by the harness's quiet-machine checks were retried, and no refused run is used.

- A 12-layer, 384-wide BERT encoder (the bge-small shape, synthetic weights) takes 36-45% less time per forward pass at 8 to 128 tokens, and encoding batches of 1 to 32 texts takes about 45% less time. The attention kernel benchmark alone takes 39-47% less time and `matmul_bt` 50-53% less on the encoder's projection and feed-forward shapes. These figures span every change since 0.14.0; no single change is isolated as their cause.
- WordPiece tokenization takes 24-39% less time for 10- to 200-word texts through the BERT tokenizer. With the double-array trie it takes 34-41% less for one text of 16 to 1,024 words and 42-43% less for batches of 1 and 8 texts; batches of 32 and 128 texts are unchanged.
- CPU attention softmax (`softmax_attention`, 12 heads, 16 to 128 tokens) takes 74-106% more time than in 0.14.0. Since 0.15.0 it computes an accurate `exp` in place of a bit-trick approximation whose ratio to `exp` ranged from 1.000 to 1.061, an error that does not cancel when the row is normalized ([#2234](https://github.com/ohdearquant/lattice/pull/2234)).
- CPU LayerNorm at hidden size 384 takes about 27% more time. It now accumulates each row's mean in f64 and centres the variance on that exact mean, so constant rows return `beta` and rows with a large offset get a correct variance ([#2743](https://github.com/ohdearquant/lattice/pull/2743), [#2757](https://github.com/ohdearquant/lattice/pull/2757), [#2765](https://github.com/ohdearquant/lattice/pull/2765)). The forward-pass figures above include both of these costs.
- The elementwise CPU kernels, the f16 KV cache, the grammar mask, the QuaRot Hadamard transform, the int8 dot product and the five attention dispatch variants show no slower group. The dispatch benchmark's direct-call baseline, which times a function defined in the benchmark file itself, moved from 1.4 to 1.7 ns.

These figures were measured at the commit this release is cut from. The release adds only the version bump, these notes and an ADR amendment.
