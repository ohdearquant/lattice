# lattice v0.17.0

**Date**: Unreleased
**Previous**: v0.16.0

## Changelog

### Breaking changes

#### Gemma and ERNIE unknown-token declarations

Gemma and ERNIE tokenizer loaders now reject an explicit `model.unk_token: "<unk>"`
declaration when `<unk>` is absent from `model.vocab`, including exports that list
it only in `added_tokens`. Missing or null `model.unk_token` retains its previous
behavior. ([#2812](https://github.com/ohdearquant/lattice/pull/2812))

The two exports lattice pins as tokenizer test fixtures both declare
`model.unk_token` as `"<unk>"` and store `model.vocab` as an object:

| Export                                                                                                      | Revision                                   | Vocabulary entries | `<unk>` vocabulary ID | Matching `added_tokens` entries |
| ----------------------------------------------------------------------------------------------------------- | ------------------------------------------ | ------------------ | --------------------- | ------------------------------- |
| [google/gemma-4-E2B-it](../../crates/inference/tests/fixtures/gemma4/tokenizer/manifest.json)               | `9dbdf8a839e4e9e0eb56ed80cc8886661d3817cf` | 262144             | 3                     | One: ID 3, `special: true`      |
| [PaddlePaddle/PaddleOCR-VL-1.6](../../crates/inference/tests/fixtures/paddleocr_vl/tokenizer/manifest.json) | `c5630abae1d940eafe0697512a0325494b02ab42` | 100295             | 0                     | One: ID 0, `special: true`      |

Both list `<unk>` in `model.vocab`, so neither has the refused layout, and both
still load: the tokenizer golden tests for these two revisions pass with this
change. Other exports that declare `<unk>` only in `added_tokens` now fail to load
with the named error.

#### Qwen3 fused projection storage in `lattice-weights`

`ShardedQwenBacking` stores each layer's Q/K/V and gate/up projections once, fused:
the `q_proj`, `k_proj`, `v_proj`, `gate_proj` and `up_proj` fields are replaced by
`fused_qkv` (rows of W_q, W_k and W_v concatenated) and `fused_gate_up` (rows of
W_gate and W_up concatenated). `QwenLayerWeights::fused_qkv` and
`QwenLayerWeights::fused_gate_up` change from `Vec<f32>` to `Cow<'a, [f32]>`, borrowed
when the owner already holds the fused buffer. Code that read the per-projection
fields should take the subslices of the fused buffers, or use the `q_proj_weight`,
`k_proj_weight`, `v_proj_weight`, `gate_proj_weight` and `up_proj_weight` views on
`QwenLayerWeights`, which keep their types.
([#2785](https://github.com/ohdearquant/lattice/pull/2785))
