# lattice v0.16.0

## Breaking changes

### Removed deprecated items

0.15.0 deprecated these items and scheduled their removal for 0.16.0 (ADR-103 Amendment 21 item 4). They are removed, and their 0.15.0 paths no longer resolve. Each replacement shipped in 0.15.0, so code that compiles against 0.15.0 with no deprecation warning from these items does not need to change for their removal. Paths below are the `lattice-inference` facade paths; the owning crate is named where the item lives outside the facade. (#2658)

| Removed                                                                       | Replacement                                                                                                                                               |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SafetensorsFile::load_bert_weights` (`lattice-weights`)                      | `model::bert::weight_loading::load_weights` (`lattice-model-bert`), or the neutral reads `SafetensorsFile::view_1d`, `view_2d` and `tensor_names_iter`    |
| `SafetensorsFile::load_cross_encoder_weights` (`lattice-weights`)             | `model::bert::weight_loading::load_classifier_weights` (`lattice-model-bert`), or `SafetensorsFile::get_f32_tensor`                                       |
| `SafetensorsFile::load_qwen_weights` (`lattice-weights`)                      | `model::qwen::weight_loading::load_weights` (`lattice-model-qwen3-embedding`)                                                                             |
| `GatedDeltaNetState::new(&Qwen35Config)` (`lattice-compute`)                  | `GatedDeltaNetState::from_geometry(&GdnGeometry)`, with the geometry from `attention::gdn::qwen35_gdn_geometry(&config)` (`lattice-model-qwen35`)         |
| `LoraHook::validate_against(&Qwen35Config)` (`lattice-compute`)               | `LoraHook::validate_geometry`, called with `lora_hook::Qwen35LoraGeometry::new(&config)`                                                                  |
| `LoraHook::validate_against_bert` (`lattice-compute`)                         | `LoraHook::validate_geometry`, called with `lora_hook::BertLoraGeometry::new(num_layers, hidden_size, intermediate_size)`                                 |
| `FlatKVCacheConfig::for_qwen3` (`lattice-compute`)                            | `FlatKVCacheConfig::new`, which takes the same arguments                                                                                                  |
| `kv_cache::plan_prefix_reuse` (`lattice-compute`)                             | `kv_cache::plan_prefix_reuse_for_slot`, which also declines an entry retained for another slot                                                            |
| `OnlineRotationSpec::r3_full_attention` (`lattice-quant`)                     | `OnlineRotationSpec::attention_output_r3(&RotationTarget, seed, block_size)`, with the target from `quant::quarot::plan::qwen35_rotation_target(&config)` |
| `OnlineRotationSpec::r4_dense_mlp` (`lattice-quant`)                          | `OnlineRotationSpec::mlp_down_r4(&RotationTarget, seed, block_size)`                                                                                      |
| `OnlineRotationSpec::validate(Option<&Qwen35Config>)` (`lattice-quant`)       | `OnlineRotationSpec::validate_target(Option<&RotationTarget>)`                                                                                            |
| `OnlineArtifactDescriptor::validate(Option<&Qwen35Config>)` (`lattice-quant`) | `OnlineArtifactDescriptor::validate_target(Option<&RotationTarget>)`                                                                                      |
| `RotationPlan::qwen35_residual_stream_linear_layers` (`lattice-quant`)        | the free function `quant::quarot::plan::qwen35_residual_stream_linear_layers`                                                                             |
| `backward::simd` (`lattice-inference`, `train-backward` + `test-utils`)       | `backward::dispatch`                                                                                                                                      |

`ShardedSafetensors::load_qwen_weights_owned`, the fourth deprecated weight loader, was already removed in this release by #2586. Use `lattice_model_qwen3_embedding::weight_loading::load_owned_weights`, then `OwnedQwenWeights::assemble_borrowed_weights`, keeping the owner alive for the borrowed weights. For model-neutral owned reads, use `TensorSource::get_f32_tensor_owned`. These are low-level, Unstable APIs. The `backward::dispatch` replacement above requires both `train-backward` and `test-utils`.

Two behaviour changes follow from the removals:

- Installing a LoRA hook now calls only `LoraHook::validate_geometry`. Through 0.15.0 it also called the deprecated `validate_against` or `validate_against_bert`. Both methods are gone from the trait, so a `LoraHook` implementation that still defines either one no longer compiles: move that check into `validate_geometry`. An implementation that defined neither keeps the default and behaves as before. `lattice-tune`'s `LoraAdapter` already implements `validate_geometry`.
- The constructor-specific errors returned by `OnlineRotationSpec::attention_output_r3` and `mlp_down_r4` name those constructors instead of the removed `r3_full_attention` and `r4_dense_mlp`. Errors from the shared block-count check, which both constructors call, name only the axis (for example `num_attention_heads`), as in 0.15.0.

### lattice-serve: request fields, context callbacks and completion budgets

`lattice_serve::serve::contract::ValidatedChatRequest` gained `total_token_cap: Option<usize>` and `min_p: Option<f32>` in #2419. `max_completion_tokens` now acts as a cap on all generated tokens, and `min_p` carries the validated min-p threshold. The struct has only public fields, so code that builds it with a struct literal no longer compiles. Add both fields. With `None` in each, behaviour matches 0.15: there is no total cap, and min-p stays at the generation config's default (0.0, disabled, unless a profile sets it). Code that only reads the struct, or gets it from request validation, needs no change.

`lattice_serve::serve::contract::normalize_request_with_context_and_budget` now passes a fourth argument to its context-check callback: `Option<usize>` for the total token cap. Update three-argument closures and account for that cap during admission. The doc-hidden public `lattice_serve::serve::prepare::PreparedChatRequest` also gains `total_token_cap: Option<usize>`; external struct literals must supply it (`None` retains the legacy behavior). (#2419)

`max_completion_tokens` counts reasoning tokens, forced delimiters and answer tokens together, so a request may exhaust its budget during reasoning. Equal non-null `max_tokens` and `max_completion_tokens` values use the total cap; conflicting values remain errors. Requests using only `max_tokens` retain the legacy additive reasoning/delimiter allowance. Both servers check completed results against the cap; streaming deltas already sent before an over-cap result cannot be recalled. The experimental adapter-free Metal MTP batch path also uses the effective cap. (#2419, #2488, #2487)

### BPE tokenizer loading and token IDs

- BPE `tokenizer.json` loading now refuses unsupported model settings that 0.15.0 silently ignored: non-empty `continuing_subword_prefix` or `end_of_word_suffix`, enabled `fuse_unk` or `byte_fallback`, and non-zero `dropout`. Malformed values are also refused. These return `InferenceError::Tokenizer` with `unsupported BPE model field <field>` in the message. `ignore_merges` must be a boolean or null, and `unk_token` must be a string or null; their errors are `BPE ignore_merges must be a boolean or null` and `BPE unk_token must be a string or null`. Omitted fields and their supported empty, false, zero or null defaults remain accepted. (#2623)
- Token IDs can change for BPE tokenizers declaring `ignore_merges: true`, `unk_token: null`, or a leading special token in a `TemplateProcessing` post-processor. Exact byte-encoded vocabulary matches now bypass merges when requested; explicit null disables the inferred unknown token; the declared leading BOS is now prepended. The BPE embedding identity program changes from `bpe-single-v1` to `bpe-single-v2` and records `ignore_merges`, so existing BPE embedding identities change. (#2623, #2624)

### WordPiece and Unigram token IDs and embedding identities

- WordPiece emits one whole-word unknown token when suffix matching fails or a word exceeds `model.max_input_chars_per_word`, instead of keeping a matched prefix. The default limit is 100 Unicode scalar values; zero is allowed. It honors `model.unk_token` and refuses malformed settings or a configured unknown token absent from the vocabulary. The embedding identity program changes to `wordpiece-single-v2` and records the limit, so identities change even where token IDs do not. (#2585)
- SentencePiece Unigram uses a uniform unknown penalty, then groups adjacent unknown spans. A grouped span uses an exact vocabulary piece when available, otherwise the unknown token spelling or complete byte fallback as applicable; it does not always become one ID. Known pieces still separate spans. The embedding identity program changes to `sentencepiece-single-v2`, so existing identities change. (#2587)

### LoRA factor tensor names

PEFT and MLX loaders reject noncanonical layer indices in recognized factor tensor names, such as `03` or `+3`. Rename those indices to their canonical decimal spelling (`3` in these examples); the loader does not normalize them automatically. This does not validate arbitrary unrecognized tensor names. (#2571)

### Model-cache validation and download staging

- Cache hits require the supported model's own tokenizer file. With valid cached weights but only the wrong tokenizer, `ensure_model_files` now returns `InferenceError::ModelNotFound` in offline or download-disabled builds, instead of the I/O error from opening the missing required tokenizer. (#2657)
- Downloads now use persistent `.<artifact>.lock` files. A symlink, directory or other non-regular entry at that lock path, previously ignored, causes `InferenceError::Io` with `InvalidInput` and `staging lock is not a regular file: <path>`. Downloading into a partial cache requires access to these lock files. (#2666, #2671)

### Qwen3.5 native Q4 loading and doctor diagnostics

- Native Metal Q4 loading now rejects checkpoints containing both `model_language_model_embed_tokens_weight.q4` and `model_embed_tokens_weight.q4`, rather than loading the canonical namespace and ignoring the flat anchor. Exactly one regular embedding anchor must be present; even an unused opposite anchor that is a symlink or non-regular entry is refused. Missing-anchor errors now read `missing Q4 embedding file <path>`; anchor refusals read `Q4 embedding anchor <path>: final component is a symlink` or `Q4 embedding anchor <path> is not a regular file`, replacing later file-opening errors. (#2667, #2672)
- `lattice doctor` rejects ambiguous Qwen3.5 embedding namespaces. For Q4 manifest embedding entries, it checks the native filename the loader opens, rather than accepting a manifest alias or counting a directory or symlink as present. An alias produces a warning; a missing or invalid native embedding blocks readiness. Q4 header sampling now uses a trusted regular file, skipping refused candidates in filename order and reporting the first refusal if none qualifies. Checkpoints that 0.15.0 reported ready through an alias or an untrusted sample can now be reported not ready. (#2667, #2674, #2677, #2679, #2686)
- `lattice doctor` text now escapes control characters, Unicode format characters, and line/paragraph separators in paths, quantization labels, missing-tensor entries, warnings and blocking reasons. Its `Error:` failure line uses the same policy and retains exit status 1. Literal backslashes are doubled so they remain distinguishable from emitted escapes. Scripts matching these lines must account for the escaped text and the new `Warning:` lines. (#2679, #2686, #2689, #2695)

### JSON Schema numeric literal intersections

- `oneOf` now rejects overlapping branches whose `const` and `enum` use equivalent integer and float spellings, such as `{"oneOf":[{"const":1,"enum":[1.0]},{"const":1}]}`. These previously compiled; they now return `SchemaError` with `oneOf branch 1 overlaps an earlier branch on literal value 1: oneOf requires mutually exclusive branches`. (#2681)
- Integer/float literal equality is limited to integral floats with magnitude below 2^53. A typed `const`/`enum` intersection that relies on equality at or beyond that boundary can now fail with `unsatisfiable typed non-string literal intersection`; for example, `{"type":"number","const":9007199254740992,"enum":[9007199254740992.0]}`. Use matching numeric representations for such literals. (#2685)

Typed non-string `const` and `enum` values now intersect with the declared type and with each other. Empty intersections return `SchemaError`; directly empty union alternatives can be dropped, while nested or referenced errors still propagate. Integer-typed literals accept exact JSON integer representations across their native range; retained integral float representations must have magnitude strictly below 2^53. Unsupported retained floats at or beyond that boundary return a representation-range error. A `const` excludes nonmatching enum members before their range checks. Use exact integer representations for large integer literals. These checks do not provide a general JSON Schema validator. (#2573, #2577, #2650)

### Rescheduled to 0.17.0

ADR-103 Amendment 21 also planned to move the family configurations, weight bundles and model policy out of `lattice-arch` and the lower crates in 0.16.0; that multi-PR refactor had not started at the 0.16.0 cut, so it is rescheduled to 0.17.0 (ADR-103 Amendment 26).

## Added

- `lattice list` lists model-cache entries with completeness, file sizes, symlinks and partial-download counts, without loading models or accessing the network. It reports unknown or renamed model directories and caches with only the wrong tokenizer as incomplete. Partial-file counts include both `.part` and `.part-<pid>-<sequence>` files. (#2576, #2657, #2666)
- `lattice_model_io::download::has_cached_model_files` checks for `model.safetensors` and the model's required tokenizer using a canonical supported directory basename. Unknown or non-UTF8 basenames return false. This is a file-presence check, not checksum verification. (#2576, #2657)
- `lattice_model_io::download::materialize_pinned_config(model_name, cache_dir)` explicitly materializes a missing managed-model `config.json` from its pinned revision, verifies its SHA-256 and publishes it without replacing an existing file. It returns `ConfigMaterialization::Created` or `AlreadyVerified`; existing files must match the pin. Normal model loading does not call this opt-in API. Staging-name exhaustion returns `InferenceError::Io` with `ErrorKind::AlreadyExists` and `could not allocate a unique staging file`. (#2409, #2666)
- The new doc-hidden public helper `lattice_arch::qwen35_tensors::inspect_q4_embedding_anchor` returns `std::io::Result<Option<std::fs::Metadata>>`. A regular file returns `Some(metadata)` and an absent anchor returns `None`. Symlinks and non-regular files return `ErrorKind::InvalidData`; other inspection errors retain their original I/O kind. (#2674, #2677)
- `lattice_weights::q4_weights::MERGED_QKVZ_CACHE_PREFIX` exposes the `merged_qkvz_` prefix used by the Metal loader and excluded from doctor's Q4 sampling and directory inventory. (#2689)
- The standalone `lattice_serve` HTTP server accepts per-request `min_p` from 0 to 1 and returns HTTP 400 `invalid_min_p` for invalid values. Omitted or null values retain the generation default. The unified `lattice serve` continues to accept and ignore this field. This exposes the existing sampler setting. (#2419)
- `lattice_serve::serve::total_completion_cap_exceeded` checks whether a completed result exceeds an optional total cap; equality and `None` are not violations. The doc-hidden, unstable `serve::stream_usage` module shares `Usage`, `StreamingUsage`, `UsageChunk` and `usage_chunk` between HTTP entry points. The existing `include_usage` wire policy is unchanged. (#2488, #2552, #2565)
- The Unstable `lattice_compute::kv_cache::PagedKVCache::try_append_kv_layer` returns `InvalidInput` for invalid vector dimensions, layer indices or non-finite Q8 input before changing the cache. It does not advance the sequence. Pool exhaustion and unsupported LRU growth can still panic; non-finite f32 storage is not rejected by this Q8-specific check. Page-table front eviction is now amortized constant-time. (#2371, #2372)
- The default-off `lattice-grammar/lazy-mask` feature adds experimental, doc-hidden `lattice_grammar::lazy::LazyGrammarEngine`. It computes trie masks on demand and caches them under a caller byte budget and a 256-entry limit, avoiding eager state enumeration at construction. The budget is not a process-memory or cache-miss latency bound. Serving continues to use the eager engine. (#2447, #2581)
- `lattice embed --model <DIR> --text <TEXT>` loads a local BERT-compatible model and prints one finite, full-dimension embedding as a JSON vector followed by a newline. Text is literal; the command does not add query/passage prefixes, download a model or batch inputs. (#2386)
- The doc-hidden, Unstable `lattice_compute::audio::WhisperLogMelPlan` extracts 128-bin, mel-major log-mel features from finite mono 16 kHz f32 PCM longer than 200 samples. Its 400-point FFT reuses frame scratch; each clip still allocates output. The Qwen2-Audio processor accepts a single clip of 1–480,000 samples, pads it to 30 seconds and returns 128 × 3,000 features, a valid-frame mask and an audio-token count. Very short clips can have zero audio tokens. These are feature-preparation APIs, without audio decoding or resampling. (#2448, #2452, #2579)
- The default-off `qwen2-audio-stem` feature adds doc-hidden, Unstable CPU f32 Qwen2-Audio stem, encoder-layer, encoder and projector building blocks using caller-supplied weights. Shapes, finite inputs, per-array 16-million-element limits and a 10-billion-MAC budget bound the path. Padded query rows are computed; output rows are not automatically truncated to the valid audio-token count. This is not a checkpoint loader or complete audio model. The feature also exposes the Unstable scalar `lattice_compute::forward::cpu::gelu_exact`. (#2454, #2455, #2457)
- The default-off `gdn-state-observer` feature adds an experimental, doc-hidden thread-local CPU observer for GDN S-matrix health across f32, f16, Q8 and NEON paths. It does not observe convolution state or Metal, prevent non-finite values, or collect other threads' work; callback panics propagate. (#2439, #2456)
- Experimental, doc-hidden `lattice_weights::mxfp4` and `nvfp4` CPU decoders write into caller-provided f32 storage. MXFP4 uses 32-value E2M1/E8M0 blocks; NVFP4 uses 16-value E2M1/UE4M3 blocks in unswizzled row-major order with a global multiplier. The `mxfp4_safetensors::dequantize_mxfp4_safetensors` helper reads an explicitly named same-file U8 `<stem>_blocks`/`<stem>_scales` pair and expands it in checkpoint order. There is no automatic model dispatch or inference integration, and decoded outputs may be non-finite. (#2423, #2434, #2557)
- Offline comparison tooling adds `quality_compare` and local Qwen3.5 CPU/HF generation-dump producers for fixed-length greedy comparisons. The HF producer isolates requested generation settings from checkpoint defaults and retains a forced-EOS control. Comparison is report-only; tokenizer parity is a separate preflight, and dumps record requested settings rather than a fully resolved HF configuration. BGE-small embedding tooling pairs a local Lattice producer with the existing sentence-transformers reference adapter, checking snapshot metadata, token IDs and normalized vectors. These tools do not download checkpoints or establish a new model-quality result. (#2450, #2451, #2582, #2460)
- Doc-hidden `lattice_arch::qwen35_tensors` helpers expose the flat/nested namespace constants, `resolve_tensor_prefix`, `qwen_layer_tensor_prefix_with_prefix` and `qwen_required_tensor_names_with_prefix`. The resolver selects exactly one embedding anchor and refuses both or neither; the string-building helpers are not independent checkpoint validators. (#2649)
- On macOS with `metal-gpu`, doc-hidden `lattice_metal_runtime::measurement::completed_command_buffer_gpu_ms` returns a finite positive GPU span in milliseconds or an error for unavailable/invalid timing or an incomplete command buffer. It is unsupported repository measurement plumbing and neither waits for completion nor acquires measurement locks. (#2645)
- Metal Qwen3.5 decode attention uses 128-token partitions and a direct path for caches of at most 128 tokens. Finer partitioning increases partial-attention scratch storage; this note makes no general latency or numerical-equivalence claim. (#2549)
- Metal Qwen3.5 Q8_0 lm-head evaluation reads the packed Q8_0 table for decode, prefill and perplexity rather than the f16 table. Logits, perplexity and generated tokens can change; the f16 table remains for CPU input-embedding lookup. (#2548, #2550)
- NEON attention softmax uses a degree-four exponential approximation while retaining range reduction and masked-zero handling. PaddleOCR-VL cached CPU generation reuses decode scratch throughout a request and releases prefill logits after selecting the first token; the public ERNIE-4.5 `kv_decode_step` still returns independent owned logits. These changes do not promise an allocation-free path, bitwise-identical output or a universal speedup. (#2516, #1988)
- On macOS, `bench_serve_http` requires a cooperative supervisor lock receipt before starting a server or sending requests. Direct runs must use `--unsupervised` and are labelled uncertified; the receipt does not prove supervisor liveness. `backward_stage0` now observes which scalar or Accelerate backend its linear-VJP preflight executed and requires `train-backward,test-utils,backward-dispatch-observer`. This enables doc-hidden `lattice_compute::forward::cpu` probes `MatmulBackendCounts`, `observe_matmul_backends` and `with_scalar_matmul_fallback`, not production telemetry. (#2483, #2442)
- The Metal `decode_profile` example accepts `LATTICE_DECODE_PROFILE_PREFILL` to choose a synthetic prompt length, defaulting to 256 for absent, zero or unparsable values. It is an example-only setting, not a serving option or arbitrary-size admission guarantee. (#2547)

## Fixes

- Concurrent downloads of the same artifact share a lock and reuse the verified publication. Downloads use unique staging files, remove failed stages, and verify the pinned SHA-256 before publishing the final file. Existing artifacts in a partial cache are reverified before fetching the next file; checksum mismatches identify the final artifact path. (#2666, #2671)
- Native Metal Qwen3.5 Q4 loading accepts flat `model.*` tensor names as well as `model.language_model.*`, selecting one namespace consistently. `lattice doctor` uses the checkpoint's namespace for required-tensor reporting, including flat tensor hints when the embedding is missing. (#2667, #2674, #2677)
- JSON Schema `$ref` checks accept redundant numeric `const` and `enum` siblings such as integer `1` versus float `1.0`. `oneOf` overlap checks no longer equate large float representations with integer literals at or beyond 2^53. (#2685)
- PEFT adapter configs accept `exclude_modules: []` as no exclusions, matching omitted or null exclusions. Empty `target_modules` and malformed exclusion entries remain errors. (#2697)
- `dequantize_row_q3_0` bounds its allocation and decoding by the complete Q3 blocks actually present, avoiding capacity overflow from a huge requested count on a small input. It still returns at most the requested number of values and ignores incomplete trailing blocks; genuinely large outputs remain subject to allocation limits. (#2699)
- Both chat servers reject nonempty or malformed `messages[].tool_calls` with HTTP 400 `unsupported_feature`, instead of silently omitting calls from the prompt. Omitted, null and empty-array history remain accepted; `role: "tool"` remains unsupported. They also reject `n: 0` instead of generating one completion. (#2419)
- Model-agnostic `generate_with_speculation` reserves room for the verifier's bonus token before invoking verification, keeping positions below `prompt_len + max_new_tokens`. Metal self-speculation no longer includes a stop token in committed verification state. (#2491, #2497)
- Q8 KV append checks both K and V before writes, avoiding partial cache mutation on invalid input. `PagePool` rejects invalid, never-allocated or double frees before mutation in all builds; the private Q8 pool follows the same rule. These changes do not make every cache allocation or capacity failure recoverable. (#2371, #2422, #2543)
- `GatedDeltaNetState::restore_from` checks both saved-buffer lengths before copying, preserving state if it panics on a mismatch. New `try_restore_from` reports `InvalidInput` for the same mismatch. Matching lengths alone do not establish matching model geometry. (#2445)
- `ShardedSafetensors::tensor_dtype` opens the referenced shard header and propagates opening errors. An unindexed tensor now returns `MissingTensor` instead of `Ok(None)`; an indexed tensor absent from that header returns `None`. The query does not validate payload bytes. (#2453)
- BERT configuration validation bounds individual vocabulary/type-vocabulary sizes at 4,000,000, hidden/intermediate widths at 1,048,576, layers at 4,096, attention heads at 8,192 and positions at 4,194,304, inclusively. Inferred layer counts use checked arithmetic. Validation errors identify the actual JSON or inferred-safetensors source. These are individual bounds, not a guarantee every dimension product or allocation fits. (#2527, #2530, #2531)
- BERT encoding checks calculated scratch requirements against an inclusive 4 GiB cap. Single encoding checks after tokenization and before scratch allocation; packed encoding splits tokenized inputs into ordered sub-batches and rejects an individually oversized input. Cross-encoder construction checks the maximum pair after BERT loading and before classifier loading, and hooked scoring checks the actual pair before buffers. The cap does not cover model weights, tokenization, outputs or total process memory. (#2559)
- Qwen embedding configuration parsing rejects derived-size overflow. Gemma 4 and EmbeddingGemma 2 reject normalization epsilon values that are not finite and positive in their f32 representation; positive subnormal values remain valid. (#2534, #2537, #2538)
- Model-format detection ignores non-regular generic Q4/GGUF candidates, follows symlinks to regular files, ignores broken links and propagates other metadata errors. Native Q4 embedding anchors retain the stricter policy described above. Tokenizer vocabulary validation rejects duplicate IDs even when one token is empty. (#2535, #2536)
- Qwen3.5 configuration treats explicit `eos_token_id: null` like an omitted field, using the existing preset token 248044 for flat and wrapped text configurations. The field remains a single `u32`; EOS arrays and invalid types are not accepted by this change. (#2553, #2567)
- JSON Schema compilation prunes alternatives that cannot derive a finite value and rejects a nonproductive root with `unsatisfiable schema: no finite JSON value`. Required impossible values and recursion without a finite base case are refused; optional impossible properties can be omitted, and productive recursion remains supported. This does not change the PDA's empty-rule convention. (#2652)
- `ThreadSafeLruCache` compacts stale order records above twice its saturating entry capacity while preserving live recency. This bounds bookkeeping records, not heap bytes or retained allocation capacity. Q8 matrix row-scale allocation failures now return contextual errors through a fallible reserve; the data buffer is not made fallible by that change. (#2584, #2592)
- CPU Qwen3.5 F32/F16 loading accepts flat `model.*` and nested `model.language_model.*` names, selecting exactly one embedding anchor and applying its namespace consistently to required tensors. Finding both anchors returns `InvalidSafetensors`; finding neither returns `MissingTensor`. The `lm_head` name stays top-level. (#2562)
- Qwen Metal initialization diagnostics no longer hardcode a model size or f16 weights, and label the resolved projection-weight format separately. (#2558)
- Gemma 4, ERNIE-4.5 M-RoPE and Metal cached ERNIE RoPE table builders share the public `lattice_compute::gemma_rope::rope_sin_cos` implementation, avoiding call-site-dependent last-bit differences for identical angles. This does not promise cross-platform bit identity or apply to every RoPE call. (#2521)
- The WGPU benchmark checks warmup failures and reports completed forwards, explicit submit counts and host timing per case, including 3- and 137-token cases. It removes the CPU-encode/GPU-forward speedup column because those timings cover different work. Both benchmark arms acquire the macOS measurement guard even without `metal-gpu`. EmbeddingGemma2 Metal timing reports zero for unavailable or invalid timestamp spans while failed command buffers still return errors. (#2589, #2593, #2440, #2645)
- Toto 2.0 configuration parsing computes its default feed-forward width only when `d_ff` is absent or null and refuses widths and layer counts that the weight loader or forward pass cannot represent. Each refusal returns `UnsupportedModel`, like the parser's other refusals: an unrepresentable default width (`Toto 2.0: default d_ff exceeds usize`), `d_ff = 0`, a `d_model` whose `4 * d_model` or a `d_ff` (explicit or default) whose `2 * d_ff` does not fit in `usize`, a `patch_size` whose loader widths do not fit, a head width whose attention projection width `3 * num_heads * head_dim` does not fit, and a `num_layers` with no representable layer-vector layout. Earlier parser refusals keep their order. These checks cover parsed configurations and representability only: a representable but very large `num_layers` can still exhaust memory, and a configuration built directly in code bypasses them. (#2703, #2724)
