# lattice v0.19.0

**Date**: 2026-11-29
**Previous**: v0.18.0

## Changelog

### Embedding identity

#### all-MiniLM-L6-v2 is truncated at 256 tokens

The native embedding service truncates an all-MiniLM-L6-v2 input at 256 tokens, special tokens included: the
`max_seq_length` of the model's sentence-transformers configuration. It truncated at the checkpoint's 512 positions
before, so an input longer than 256 tokens now embeds to a different vector. Its embedding identity moves from
`all-minilm-l6-v2-native-v1` to `all-minilm-l6-v2-native-v2`, so vectors from the two limits carry different
identities. Vectors stored from an earlier release carry `all-minilm-l6-v2-native-v1`; an index built from them is
rebuilt under `all-minilm-l6-v2-native-v2`. `EmbeddingModel::max_input_tokens` already reported 256 for this model, so
chunks sized from it are unaffected.

The WebAssembly embedder gains `limitInputTokens`, which lowers its input length cap, and the
`@khive-ai/lattice-embed-wasm` package applies the limits the native service truncates at: 256 tokens for
all-MiniLM-L6-v2 and 128 for paraphrase-multilingual-MiniLM-L12-v2.
([#3029](https://github.com/ohdearquant/lattice/pull/3029))

### Breaking changes

No public item of the published crates was removed or changed its signature.

#### Hidden `lattice-serve` modules

The `#[doc(hidden)]` modules of `lattice-serve` are not a stable API, and this change is listed only so that code
reaching into them is not surprised:

- `serving_provider::LatticeOpenOptions` gains `cpu_weight_store: CpuWeightStore`.
  ([#2986](https://github.com/ohdearquant/lattice/pull/2986))

### Changed outputs

- **Softmax exponentials on x86 and NEON.** The AVX2+FMA softmax `exp` uses relative-error minimax coefficients in
  place of the degree-5 Taylor ones, and NEON decode attention softmax uses the accurate-tier `exp` for its vector
  lanes and the standard `exp` for its tail; masked entries are handled as before. Attention probabilities change in
  their last bits. ([#3001](https://github.com/ohdearquant/lattice/pull/3001),
  [#3000](https://github.com/ohdearquant/lattice/pull/3000))

### Changed behaviour

- **Managed BERT models read their pinned tokenizer file.** `BertModel::from_pretrained`, and the digest-mode load of a
  managed model, read only `vocab.txt` when the model's checksum entry pins `vocab.txt`; a `tokenizer.json` beside it is
  not read, because the download path does not verify it. `BertModel::from_directory` is unchanged.
  ([#3010](https://github.com/ohdearquant/lattice/pull/3010))
- **BERT embedding tables shorter than encode reads are refused at load.** A `word_embeddings` table with fewer rows
  than the tokenizer's vocabulary, a `position_embeddings` table with fewer rows than the positions encode can use, and
  a `token_type_embeddings` table with no rows are refused; a cross-encoder also needs at least two
  `token_type_embeddings` rows. ([#3011](https://github.com/ohdearquant/lattice/pull/3011))
- **Qwen3-Embedding vocabulary bounds.** A load whose `embed_tokens` row count differs from the config's `vocab_size`
  is refused, and so is an encode of a token ID outside the embedding table; a BF16 `embed_tokens` tensor whose length
  does not match its shape is refused at load. ([#2989](https://github.com/ohdearquant/lattice/pull/2989),
  [#3018](https://github.com/ohdearquant/lattice/pull/3018))
- **`lattice_serve` flags.** `--port`, `--max-tokens`, `--temperature`, `--top-k`, `--top-p`, `--repetition-penalty`
  and `--reasoning-budget` with a value that does not parse stop startup with an error naming the flag instead of
  falling back to the default, and so does a non-finite `--temperature` or `--top-p` and a `LATTICE_SERVE_PORT` that is
  not a port number. Each of these flags, `--max-context` and `--max-pending` given last with no value after it is
  refused the same way.
  ([#3007](https://github.com/ohdearquant/lattice/pull/3007))
- **`lattice` diagnostics.** Error lines and `lattice doctor` report lines print control and format characters, line
  and paragraph separators, non-ASCII blank characters and backslashes escaped.
  ([#3017](https://github.com/ohdearquant/lattice/pull/3017))

### Added

- **`lattice serve --cpu-weight-store`.** `f32` (the default) or `bf16` selects how a Qwen3.5 safetensors checkpoint
  served on the CPU holds its embedding, output head and projection matrices; `bf16` keeps each one the checkpoint
  stores as BF16 in its two-byte form. Startup prints how many tensors were held each way, and a mixture-of-experts
  checkpoint refuses `bf16`. `lattice doctor --cpu-weight-store` estimates the CPU weight memory for either store, and
  `lattice_model_qwen35::model::qwen35::bf16_store_holds_as_bits` names the tensors the bf16 store holds as bits.
  ([#2986](https://github.com/ohdearquant/lattice/pull/2986))
- **WordPiece-only loading.** `lattice_tokenizer::common::load_wordpiece_vocab` and
  `load_wordpiece_vocab_with_report` load `vocab.txt` without reading any other tokenizer file, and
  `lattice_model_io::download::pinned_tokenizer_filename` names the tokenizer file a managed model's checksum entry
  pins. The new items are marked unstable. ([#3010](https://github.com/ohdearquant/lattice/pull/3010))

### Performance

- **BPE pre-tokenizer.** Letters and combining marks are tested with a range lookup over the Unicode class tables.
  ([#3026](https://github.com/ohdearquant/lattice/pull/3026))
- **Gemma 4 probe prefill.** `Gemma4Model::generate_greedy_with_probe` projects vocabulary logits only at the last
  prompt position. ([#3002](https://github.com/ohdearquant/lattice/pull/3002))

### Fixes

- **JSON Schema grammars.** A string-typed `$ref` inside `anyOf` or `oneOf` whose target is a type array that includes
  `string`, an empty schema or annotations only compiles to strings; as for a plain string schema, `pattern`,
  `minLength`, `maxLength` and `format` on such a target are not enforced, and recovery never bypasses an assertion on
  the referencing node. ([#3019](https://github.com/ohdearquant/lattice/pull/3019))
- **Qwen3.5 Metal mixture-of-experts routing trace.** Each traced device route has its own buffer, so a later token
  can no longer overwrite a route before the trace publishes it.
  ([#3012](https://github.com/ohdearquant/lattice/pull/3012))
- **`lattice` command output.** `lattice chat` stops when its output cannot be written, and `lattice forecast` writes
  nothing, and leaves an existing output file as it was, when a forecast fails. ([#2991](https://github.com/ohdearquant/lattice/pull/2991))

### Rescheduled

The move of the family configurations, weight bundles and model policy out of `lattice-arch` and the lower crates
(ADR-103 Amendment 27) is tracked in [#2899](https://github.com/ohdearquant/lattice/issues/2899). It merges only while
`main` carries an unreleased minor version, ships in a `0.x.0` release and never in a patch, and that release's notes
carry the path map for the lower-crate paths it moves.

Status at 0.19.0: not started.
