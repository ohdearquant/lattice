# lattice v0.10.0

Minor release, and under Cargo's rules for a `0.x` line that means a breaking one: `^0.9`
does not admit `0.10`, so the minor position is where an incompatible change goes. **Four
breaking changes** are listed below. The first two are reachable from a default build; the
other two sit behind optional features that are off by default.

The headline is a new model family. PaddleOCR-VL now runs end to end on CPU — tokenizer,
image preprocessing, vision encoder, projector, and the ERNIE-4.5 text decoder — each stage
gated against Hugging Face reference outputs rather than against itself. Alongside it:
Metal speculative decoding, two new sampling methods, `/v1/embeddings` on the standalone
serving binary, and a sealed contract for native embedding preparation.

## New: PaddleOCR-VL, end to end on CPU

The full document-OCR path is in place and each stage landed behind its own differential
gate against HF goldens, so a stage is only claimed once its numbers match the reference:

- **Tokenizer** — the ERNIE vocabulary runs through the existing SentencePiece-BPE engine.
- **Image preprocessing** — bit-exact against the reference resampler, including the
  `smart_resize` rounding-then-scaling behavior, so the patch grid a prompt produces is the
  one the reference produces.
- **Vision encoder and projector** — the NaViT-style ViT forward and the projection into
  the decoder's embedding space.
- **Text decoder** — the ERNIE-4.5 dense decoder forward.
- **End-to-end forward** — vision, projector, and decoder composed, compared against HF
  greedy output.
- **KV-cached greedy decode**, with a last-row logits path so the decoder computes the
  terminal norm and `lm_head` only for the position that needs them. The KV cache is
  reusable and has a model-bound constructor rather than being rebuilt per call.

## New: Metal speculative generation

Speculative decoding on the Metal path is now state-owned: the draft/verify cycle lives with
the model state instead of being reassembled per request. Rejection is typed rather than
inferred, including the mixture-of-experts case, and the n-gram search that proposes drafts
is bounded rather than open-ended.

## New sampling: min-p and top-n-sigma

Two sampling methods join the existing set, both implemented for parity with their reference
definitions rather than approximations of them.

## `POST /v1/embeddings` on `lattice_serve`

v0.9.0 added the OpenAI-compatible embeddings route to `lattice serve`. The standalone
`lattice_serve` binary now exposes it too, so the two serving entry points no longer differ
on which routes exist.

## Sealed native embedding preparation and attestation

Native embedding preparation now has an explicit, sealed contract between the `embed` and
`inference` crates: preparation inputs and the attestation describing what was prepared are
typed rather than passed as loose values, so a mismatch between what a caller intends and
what the engine did is a compile-time or checked-at-boundary question instead of a silent
divergence. A one-command embedding-drift gate runs across the production models.

## Adapter routing

The route to refit to route loop now closes in process: an adapter router can be reloaded
without tearing down the engine. On the Metal path, adapter control is serialized against
generation on the worker queue, so a reload cannot interleave with a decode in flight.

## Breaking change 1: `TokenizedInput` gained a field

`tokenizer::common::TokenizedInput` has a new public field:

```rust
pub pre_truncation_len: usize,
```

It carries the token count produced **before** any maximum-sequence-length truncation was
applied. It equals `real_length` when the tokenizer did not truncate and is larger when it
did. Context-window admission checks must compare against `pre_truncation_len`, not
`real_length`: `real_length` can never exceed the tokenizer's own `max_seq_len`, so on a
model where `max_seq_len <= max_position_embeddings` it cannot signal an over-limit input at
all. That gap is what this field closes.

The struct has no private fields and is not `#[non_exhaustive]`, so it is constructible from
outside the crate and a struct literal that names every field stops compiling. Reading the
struct, matching on it, or constructing it with `..Default::default()` is unaffected.

## Breaking change 2: three generation config structs are now `#[non_exhaustive]`

`model::GenerateConfig`, `sampling::SamplingConfig`, and `serve::GenerateConfigSnapshot`
carry `#[non_exhaustive]`. Their doc comments already described them as unstable and
expected to gain fields; the attribute makes that contract enforced instead of advisory, so
adding a field in a later release stops being a breaking change.

The cost is paid once, here. A `#[non_exhaustive]` struct cannot be built with a struct
expression from another crate, and that includes functional-update syntax — `GenerateConfig
{ max_tokens: 128, ..Default::default() }` no longer compiles outside `lattice-inference`.
Build from the default and assign instead; every field stays public and writable:

```rust
let mut cfg = GenerateConfig::default();
cfg.max_tokens = 128;
```

`GenerateConfig` and `SamplingConfig` both implement `Default`.
`GenerateConfigSnapshot` is produced by `From<&GenerateConfig>` rather than constructed
directly, so sealing it changes nothing for callers that read it. Reading fields, matching
on them, and mutating an owned value are all unaffected for all three.

## Breaking change 3: the Metal worker test helpers return a different receiver

`serve::metal_worker::test_client_and_jobs` and its sibling
`test_client_and_jobs_with_cap` now return `mpsc::UnboundedReceiver<WorkerMessage>` instead
of `mpsc::UnboundedReceiver<WorkerJob>`. `WorkerMessage` is a new enum that carries a
`WorkerJob` among other worker-bound messages; `WorkerJob` itself is unchanged and still
public.

Both helpers are gated behind `#[cfg(any(test, feature = "test-utils"))]`, so this affects
only consumers that enable the `test-utils` feature. Default builds see no change.

## Breaking change 4: `FullDriverConfig` gained two fields

`lattice-tune`'s `train_support::full_driver::FullDriverConfig` has two new public fields:

```rust
pub seed: u64,
pub gdn_modules: GdnModuleSelection,
```

`seed` is the LoRA initialization seed for training. `gdn_modules` selects which GDN
projections are trained and saved, and defaults to `GdnModuleSelection::Served` everywhere a
caller does not say otherwise, because an adapter carrying the other two cannot be loaded by
the Metal forward and nothing reports that until load time.

The struct is not `#[non_exhaustive]`, so an exhaustive struct literal needs both fields.
`train_support` is `#[doc(hidden)]` and gated behind the non-default `train-backward`
feature, so a default `lattice-tune` build cannot reach this type at all.

## Fixes

Correctness:

- An `mrope_section` whose declared lane counts do not match the ones actually realized is
  now rejected instead of being used.
- The Metal fused-attention shape guard rejects `head_dim != 128` rather than dispatching a
  kernel that cannot service the shape.
- The learned BERT pooler is applied before cross-encoder classification.
- BERT encoder tensor namespaces resolve correctly.
- SentencePiece BERT tokenizer layouts: the unsupported ones are rejected, and all three
  supported candidates are recognized.
- Unsupported MoE prefill is rejected on every request-facing path, not just some of them.
- Over-window embeddings input is rejected before truncation, so an oversized item fails
  with a clear error rather than being silently shortened.
- The safetensors index and the quantize manifest are read through one bounded, non-blocking
  reader.
- In the fine-tuning JSONL loader, prompt and completion are tokenized separately and EOS is
  appended.
- Adapter module selection reaches the optimizer, so the modules trained are the modules
  served.

Tooling and packaging:

- Downloaded platform prebuilds survive the npm publish preflight intact.
- The GPU measurement lock is held across a benchmark target list rather than per target,
  and per-invocation lock handoff is verified.
- Ambient load is sampled inside each measured benchmark arm, not only at phase boundaries,
  and the resulting verdict is carried into the run's status artifact — a load spike that
  starts and ends between two boundary samples used to be invisible to all of them.
- `make bench-gate` no longer asks the gate about a baseline it never writes.
- The published `lattice-inference` archive no longer carries the Gemma and PaddleOCR-VL
  tokenizer vocabularies. They are 43 MB of fixture read only by integration tests, which
  cannot run from a published crate, and they had grown the archive to the edge of the
  registry's upload limit. Excluding them takes it from roughly 10.0 MiB to 2.8 MiB.

## Perf

- The ERNIE decoder's greedy loop uses a last-row logits path.
- Frozen-prefix cache construction is parallelized across samples.

## Documentation and lint hygiene

Every broken or private intra-doc link in the workspace is fixed: links whose target is a
real public item are now written with a path that resolves from the crate root, and links to
private or feature-gated implementation details are plain code spans, since they could never
render as links in published documentation. The workspace also builds clean under
`clippy::unwrap_used` and `clippy::expect_used` for library targets — not by removing panics,
which these sites do not have (every one is an invariant the surrounding code already
establishes, several beside an `assert!` that panics on the same condition), but by carrying
each invariant as a compiler-checked `#[expect(..., reason = "...")]` justification in the
source. The practical effect is that a newly introduced `unwrap` in library code is now
visible immediately instead of being lost among pre-existing entries in a CI log.

## Upgrading

Most of this release is additive. Four changes need source updates:

- Code constructing `TokenizedInput` with an exhaustive struct literal needs the new
  `pre_truncation_len` field. Code that also performs context-window admission should switch
  that comparison from `real_length` to `pre_truncation_len`; that is the reason the field
  exists.
- Code building `GenerateConfig`, `SamplingConfig`, or `GenerateConfigSnapshot` with a
  struct expression, functional-update syntax included, must start from
  `Default::default()` (or, for the snapshot, from `From<&GenerateConfig>`) and assign
  fields.
- Code enabling the `test-utils` feature and binding the second element of
  `test_client_and_jobs` or `test_client_and_jobs_with_cap`'s return value now receives
  `WorkerMessage` values rather than `WorkerJob` values.
- Code enabling `lattice-tune`'s `train-backward` feature and building `FullDriverConfig`
  from an exhaustive struct literal needs `seed` and `gdn_modules`.
