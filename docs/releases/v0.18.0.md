# lattice v0.18.0

**Date**: 2026-11-26
**Previous**: v0.17.0

## Upgrading from 0.16.0

0.17.0 was not published to crates.io, so 0.18.0 is the first release there since 0.16.0. A project moving from the
crates.io 0.16.0 release also takes the breaking changes and changed outputs listed in the
[0.17.0 notes](https://github.com/ohdearquant/lattice/blob/main/docs/releases/v0.17.0.md).

One crate is new on crates.io with this release: `lattice-model-inkling2`.

## Changelog

### Breaking changes

#### GatedDeltaNet projection weights in `lattice-compute`

`lattice_compute::attention::gdn::GatedDeltaNetWeights` holds `in_proj_qkv`, `in_proj_z` and `out_proj` as
`WeightMatrix` instead of `Vec<f32>`. `WeightMatrix` (`lattice_compute::forward::cpu::weight_matrix`) is an enum of
an f32 store, `WeightMatrix::F32(Vec<f32>)`, and a bf16 store, `WeightMatrix::Bf16(Vec<u16>)`, whose bits are widened
exactly to f32 wherever they are read. Code that builds the struct from f32 vectors can wrap them with
`WeightMatrix::from` (or `.into()`); code that read the fields as slices should call `to_f32()`, which borrows the f32
store and widens the bf16 one, or match the `F32` variant.
([#2984](https://github.com/ohdearquant/lattice/pull/2984))

#### Qwen3.5 weight accessors

`Qwen35Model::embed_weights` returns `Cow<'_, [f32]>` instead of `&[f32]`: borrowed when the embedding table is held
as f32, widened when it is held as bf16. Under the `train-backward` feature, `Qwen35Model::head_weights` returns
`(Cow<'_, [f32]>, &[f32], Cow<'_, [f32]>)` instead of three slices, with the same rule for the two matrices; the final
norm stays a slice. Callers that need a slice can take `&*` of the returned value.
([#2984](https://github.com/ohdearquant/lattice/pull/2984))

#### Decode driver entry points in `lattice-arch`

`lattice_arch::decoder::driver::run` and `run_into` take the request as one `&SessionRequest` in place of the five
arguments `gen_cfg`, `think_close_id`, `reasoning_newline_boundary`, `prompt_ids` and `eos_token_id`. The other
arguments keep their order. A caller builds the request once:

```rust
let mut request = SessionRequest::new(prompt_ids.to_vec(), gen_cfg.clone(), eos_token_id);
if let (Some(close_id), Some(table)) = (think_close_id, reasoning_newline_boundary) {
    request = request.with_reasoning_close(close_id, table);
}
driver::run(session, &request, streaming, cancel, on_push, decode_delta, /* ... */)?;
```

`with_reasoning_close` sets the reasoning-close token and the line-ending table together, both needed to enforce
`reasoning_budget`. A caller that owns its prompt and configuration can move them into `SessionRequest::new` instead
of copying them. ADR-103 Amendment 28 records the change.
([#3006](https://github.com/ohdearquant/lattice/pull/3006))

#### `MultimodalInput::total_sequence_len` in `lattice-model-io`

`lattice_model_io::multimodal::MultimodalInput::total_sequence_len` returns `Result<usize, VisionError>` instead of
`usize`, and it and `validate` return `VisionError::InvalidConfig` where the token counts or `visual_tokens * d_model`
would overflow. Callers add `?` or handle the error.
([#2994](https://github.com/ohdearquant/lattice/pull/2994))

#### Hidden `lattice-serve` modules

The `#[doc(hidden)]` modules of `lattice-serve` are not a stable API, and these changes are listed only so that code
reaching into them is not surprised:

- `serve::route::RouteRefusal` gains `Inkling2StandaloneUnsupported`.
  ([#2923](https://github.com/ohdearquant/lattice/pull/2923))
- `serving_provider::LatticeOpenOptions`, and on macOS with `metal-gpu` `StandaloneOptionPresence` and
  `StandaloneLoadOptions`, gain `restore_empty_reasoning: bool`.
  ([#2974](https://github.com/ohdearquant/lattice/pull/2974))
- `serving_host::ServingHandle::stream_lattice` takes one more type parameter.
  ([#2931](https://github.com/ohdearquant/lattice/pull/2931))

`lattice_weights::ModelFamily` gains `Inkling2`; the enum is `#[non_exhaustive]`, so this is not a break.

### Changed outputs

These fixes change what some inputs produce. The tokenizer entries move lattice toward the Hugging Face `tokenizers`
behaviour the checkpoint's `tokenizer.json` declares.

- **BPE text is split by the pattern `tokenizer.json` declares.**
  ([#2914](https://github.com/ohdearquant/lattice/pull/2914))
- **A regex `ByteLevel` pre-tokenizer beside a declared `Split` is refused at load.**
  ([#2921](https://github.com/ohdearquant/lattice/pull/2921))
- **A BPE line-break piece ends at the last break in its whitespace.**
  ([#2955](https://github.com/ohdearquant/lattice/pull/2955))
- **A declared NFC normalizer is applied before BPE pre-tokenization.**
  ([#2956](https://github.com/ohdearquant/lattice/pull/2956))
- **BPE added tokens marked `normalized` are matched against the normalized text.**
  ([#2960](https://github.com/ohdearquant/lattice/pull/2960))
- **Qwen3.5 chat prompts.** Trimming and assistant history render as the published chat template does, and each
  template marker is encoded as its own token rather than tokenized as text.
  ([#2937](https://github.com/ohdearquant/lattice/pull/2937), [#2938](https://github.com/ohdearquant/lattice/pull/2938),
  [#2943](https://github.com/ohdearquant/lattice/pull/2943))
- **Images are turned by their EXIF orientation.** `lattice_model_io::image::decode_image_bounded` applies a
  decoded image's EXIF orientation, so a rotated or mirrored photo reaches the vision models the way it displays;
  malformed orientation metadata is ignored. ([#2993](https://github.com/ohdearquant/lattice/pull/2993))
- **`lattice_forecast::prep::interp` and NaN.** A NaN query returns NaN when there are several points and the lone
  value when there is one, as `numpy.interp` does. ([#2997](https://github.com/ohdearquant/lattice/pull/2997))

### Changed behaviour

- **Added-token IDs and `vocab_size()`.** The WordPiece, SentencePiece and Gemma BPE tokenizers now report a
  `vocab_size()` that covers every added-token ID, so every ID they emit is below it. A tokenizer file whose
  added-token ID is at or past 16 times the base vocabulary plus the distinct added IDs is refused at load.
  ([#2988](https://github.com/ohdearquant/lattice/pull/2988))
- **`/v1/systemone` JSON nesting.** A request body nested more than 128 arrays or objects deep is refused.
  ([#2990](https://github.com/ohdearquant/lattice/pull/2990))

### Added

- **Inkling 2 on the CPU.** `lattice-arch` parses and validates the Inkling 2 looped-model config; the new
  `lattice-model-inkling2` crate loads the looped mixture-of-experts text decoder from a safetensors checkpoint and
  generates text through the shared decode driver; `lattice serve` serves it on the CPU, accepts `reasoning_effort`
  and returns its reasoning as `reasoning_content`. See ADR-106.
  ([#2912](https://github.com/ohdearquant/lattice/pull/2912), [#2913](https://github.com/ohdearquant/lattice/pull/2913),
  [#2918](https://github.com/ohdearquant/lattice/pull/2918), [#2920](https://github.com/ohdearquant/lattice/pull/2920),
  [#2922](https://github.com/ohdearquant/lattice/pull/2922), [#2923](https://github.com/ohdearquant/lattice/pull/2923),
  [#2927](https://github.com/ohdearquant/lattice/pull/2927), [#2929](https://github.com/ohdearquant/lattice/pull/2929),
  [#2930](https://github.com/ohdearquant/lattice/pull/2930), [#2931](https://github.com/ohdearquant/lattice/pull/2931))
- **`lattice-weights`** gains MXFP8 decoding and packed NVFP4 and MXFP8 matrix-vector products.
  ([#2910](https://github.com/ohdearquant/lattice/pull/2910))
- **`lattice-compute`** gains `matmul_bt_bf16` for weights held as bf16 bits, and `WeightMatrix`, which the Qwen3.5
  CPU weights now use. ([#2984](https://github.com/ohdearquant/lattice/pull/2984))
- **Qwen3.5 chat history reasoning.** `ChatHistoryReasoning` selects how an earlier assistant turn's reasoning block is
  rendered, with an opt-in setting that keeps an empty block and `RestoreEmpty`, which lets the next turn append to a
  held reply; `lattice serve --restore-empty-reasoning` turns it on.
  ([#2969](https://github.com/ohdearquant/lattice/pull/2969), [#2973](https://github.com/ohdearquant/lattice/pull/2973),
  [#2974](https://github.com/ohdearquant/lattice/pull/2974))
- **`lattice serve` CPU limits.** `--cpu-threads` runs CPU requests on a bounded thread pool, and the shared CPU
  admission cap is named `--max-cpu-requests`.
  ([#2978](https://github.com/ohdearquant/lattice/pull/2978))
- **`/v1/systemone` scoring** stops at a time limit, and on Metal prefills the scoring prefix its rows share once.
  ([#2964](https://github.com/ohdearquant/lattice/pull/2964), [#2965](https://github.com/ohdearquant/lattice/pull/2965),
  [#2966](https://github.com/ohdearquant/lattice/pull/2966))
- **Qwen3.5 bf16 CPU weight store.** `Qwen35Model::from_safetensors_with_options`, given
  `Qwen35LoadOptions::with_cpu_weight_store(CpuWeightStore::Bf16)`, holds each projection, feed-forward, embedding and
  head matrix that the checkpoint stores as BF16 as its bf16 bits, which halves those matrices' resident bytes and costs
  time per product; every other tensor stays f32. `weight_load_report` counts what the load held in each store. A
  mixture-of-experts checkpoint refuses the bf16 store, and training needs the f32 one. The new items are marked
  unstable. See ADR-107. ([#2985](https://github.com/ohdearquant/lattice/pull/2985))

### Performance

- **Qwen3.5 batched CPU prefill** runs attention over query tiles in parallel and the GatedDeltaNet scan one head at
  a time. ([#2979](https://github.com/ohdearquant/lattice/pull/2979), [#2980](https://github.com/ohdearquant/lattice/pull/2980))
- **Qwen3.5 tokenizer.** The pre-tokenizer pattern is split by hand, and the BPE segment call stays direct when no
  added token is normalized. ([#2957](https://github.com/ohdearquant/lattice/pull/2957),
  [#2962](https://github.com/ohdearquant/lattice/pull/2962))
- **Qwen3.5 Metal decode attention.** When each KV head serves four query heads, the flash-decode partial pass runs a
  kernel specialized for that grouping, for f32 and f16 KV caches alike.
  ([#3003](https://github.com/ohdearquant/lattice/pull/3003))

### Fixes

- **`/v1/systemone` cancellation.** CPU scoring stops inside the prefill, and Metal option scoring between prefill
  chunks, when the caller hangs up; the scoring cancel check runs before an MTP head's logit buffer.
  ([#2961](https://github.com/ohdearquant/lattice/pull/2961), [#2963](https://github.com/ohdearquant/lattice/pull/2963),
  [#2968](https://github.com/ohdearquant/lattice/pull/2968))
- **`/v1/systemone`** answers a malformed worker reply with 500.
  ([#2976](https://github.com/ohdearquant/lattice/pull/2976))
- **Qwen3.5 prefix cache.** The turn start is checkpointed when a text prompt ends at its assistant opener.
  ([#2940](https://github.com/ohdearquant/lattice/pull/2940))
- **GBNF grammars.** A comment at the end of a line no longer joins the next rule to it; a byte class range with an
  escaped endpoint, such as `[\t-\r]`, covers that range; `\xHH` escapes work in strings and byte classes, and a class
  refuses a non-ASCII `\x` escape, a `\u` escape and a descending range; a rule named like an anonymous group no
  longer collides with one. ([#2992](https://github.com/ohdearquant/lattice/pull/2992))
- **`lattice-fann`** builds its optional `futures` dependency without that crate's default features.
  ([#2995](https://github.com/ohdearquant/lattice/pull/2995))

### Rescheduled

The move of the family configurations, weight bundles and model policy out of `lattice-arch` and the lower crates
(ADR-103 Amendment 27) is tracked in [#2899](https://github.com/ohdearquant/lattice/issues/2899). It merges only while
`main` carries an unreleased minor version, ships in a `0.x.0` release and never in a patch, and that release's notes
carry the path map for the lower-crate paths it moves.

Status at 0.18.0: not started.
