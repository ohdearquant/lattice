# lattice v0.15.1

Patch release.

## Serving

- `lattice_serve` accepts `min_p` on chat requests, from 0 to 1 inclusive; any other value is refused with 400 `invalid_min_p`. `lattice serve` accepts the field and ignores it, as it does `top_k` (#2414, part of #587).
- Both servers refuse a chat message carrying a non-empty `tool_calls` with 400 `unsupported_feature`. Earlier versions accepted the message and left the calls out of the prompt. `tool_calls` that is omitted, `null` or `[]` is still accepted, and `role: "tool"` keeps its existing refusal (#2415).
- Both servers refuse `n: 0` with 400 `unsupported_feature`. Earlier versions ran it as a single completion (#2416).
- `max_completion_tokens` now caps all generated IDs, including reasoning and forced delimiters. Clients sending this field with reasoning enabled may receive fewer tokens than before; an equal pair with `max_tokens` uses the total cap. Requests using only `max_tokens` retain the additive reasoning allowance (#2419).
